BigShrimp 项目架构深度解析
BigShrimp 是一个结构高度规范、采用模块化单体架构 (Modular Monolith) 与领域驱动设计 (Domain-Driven Design, DDD) / 洁净架构 (Clean Architecture) 思想构建的 Python 桌面应用程序（基于 PySide）。

整个项目通过严密的目录划分，实现了高内聚、低耦合，各业务模块职责边界清晰，并具备完善的跨模块事件驱动机制和基础设施支持。

一、 整体架构风格与分层设计
项目采用了典型的双向解耦设计：横向按业务领域分模块，纵向在模块内部采用 Clean Architecture 分层。

横向模块划分 (modules/): 将系统垂直切分为多个独立的业务边界（Bounded Contexts），包括工作区、用户界面、AI 智能体、安全隔离、沙箱执行、代码分析以及外部桥接。

纵向分层结构 (模块内部): 每个核心业务模块内部通常包含以下标准目录：

api.py: 模块对外暴露的统一公共接口（Façade），隔离内部实现。

ports.py: 定义模块间的契约与接口。

domain/: 纯业务领域层，包含实体、值对象和核心业务规则，不依赖任何外部框架或基础设施。

application/: 应用服务层（用例层），负责编排业务流程和用例。

infrastructure/: 基础设施层，处理外部交互（如文件系统读写、数据库存储、LLM 网关、WebSocket 服务等）。

二、 核心模块详解
1. Shell 模块 (modules/shell/) —— 呈现层与 GUI 交互
负责整个 PySide 桌面端的用户界面与交互逻辑：

main_window.py: 主窗口入口，统筹全局布局。

panels/: 包含业务功能面板，如 agent_chat_panel.py（AI 对话面板）、project_tree_panel.py（项目树面板）、runner_panel.py（运行调试面板）。

presenters/: 采用 MVP（Model-View-Presenter）模式，如 agent_presenter.py、editor_presenter.py、project_presenter.py 和 runner_presenter.py，用于解耦 UI 控件与业务逻辑。

components/: 可复用UI组件，如自定义代码高亮器 (python_highlighter.py)、代码编辑器、终端等。

dialogs/: 弹窗对话框（如权限审批 approval_dialog.py、设置 settings_dialog.py）。

2. Workspace 模块 (modules/workspace/) —— 工作区与项目管理
负责项目文件的管理与脚手架生成：

Domain: 定义了项目结构树 (arch_tree.py)、代码文本 (code_text.py)、路径规则 (path_rules.py)、项目实体 (project.py)、脚手架计划 (scaffold_plan.py) 和标签状态 (tab_state.py)。

Application: 处理文件 I/O、打开项目 (open_project.py)、根据文本生成脚手架 (scaffold_from_text.py)。

Infrastructure: 本地文件系统操作 (local_fs.py) 和文件服务。

3. Agent 模块 (modules/agent/) —— AI 智能体核心
负责与大语言模型交互、处理用户意图、规划任务并执行：

Domain: 定义消息 (message.py)、计划 (plan.py)、提示词模板 (prompt_template.py)、规则 (rules.py) 和会话 (session.py)。

Application: 核心交互逻辑，如处理用户消息 (handle_user_message.py)、运行 Agent (run_agent.py)、流式回复 (stream_reply.py)。

Infrastructure:

llm/: 包含大模型网关 (openclaw_gateway.py)。

persistence/: 提示词存储 (prompt_store.py) 与会话存储 (session_store.py)。

prompt_engine.py: 提示词组装与渲染引擎。

4. Sandbox 模块 (modules/sandbox/) —— 沙箱执行与自愈
负责代码的安全执行及自动错误修复：

Domain: 治愈策略 (heal_policy.py) 与作业任务 (job.py)。

Application: 执行 (execute.py) 与自我修复 (self_heal.py) 逻辑。

Infrastructure: 执行器服务 (executor_service.py) 与自愈服务 (self_heal_service.py)。

5. Security 模块 (modules/security/) —— 安全与审计
负责权限管控与审计日志：

Domain: 审批流程 (approval.py)、权限控制 (permission.py)、安全策略 (policy.py)。

Application: 鉴权 (authorize.py) 与记录审计 (record_audit.py)。

Infrastructure: 审计日志 (audit_log.py) 与敏感信息/密钥存储 (secret_store.py).

6. Analysis 模块 (modules/analysis/) —— 代码与数据库分析
负责静态代码分析与数据库检查：

Application: 提取大纲 (extract_outline.py)、检查数据库 (inspect_database.py)、扫描入口 (scan_entry.py)。

Domain: 模式信息 (schema_info.py) 与符号定义 (symbol.py)。

Infrastructure: 分析器服务 (analyzer_service.py)、数据库检查器 (db_inspector.py)、扫描服务 (scanner_service.py)。

7. Bridge 模块 (modules/bridge/) —— 外部通信桥接
负责与外部插件、浏览器扩展或其它进程进行实时通信：

Infrastructure: WebSocket 服务 (websocket_server.py)、JSON 编解码 (json_codec.py)、Native Messaging。

Application: 分发请求 (dispatch_request.py)、处理插件事件 (handle_plugin_event.py)。

三: 共享内核与基础设施 (shared/)
shared 目录构成了整个单体应用的通用基石，供所有模块共同调用：

kernel/: 核心基础原语，包含统一错误定义 (errors.py)、全局 ID 生成 (ids.py)、标准结果包装 (result.py)。

infrastructure/:

event_bus.py: 全局事件总线，实现模块间的松耦合异步/同步通信。

command_handler.py: 命令处理器。

qsettings_store.py: 基于 Qt QSettings 的配置持久化存储。

config/: 应用配置 (app_config.py) 与 AI 配置 (ai_config.py)。

events/: 定义了跨模块的领域事件（如 agent_events.py、sandbox_events.py、workspace_events.py）。

base/: 基础类库，如可观察对象 (observable.py)。

四、 架构优势总结
高度模块化与可扩展性: 每一个功能域（如 Agent、Sandbox、Security）完全内聚。如果未来需要将某部分剥离为独立微服务或独立进程，其清晰的 ports.py 和 api.py 边界能够将改动降到最低。

职责分离清晰: UI 呈现（Shell）、核心逻辑（Domain/Application）与底层实现（Infrastructure）严格隔离，极大地提升了单元测试的可行性与代码的可维护性。

强大的跨模块协作能力: 通过 shared/infrastructure/event_bus.py 与事件定义，各个独立模块之间能够以事件驱动的方式安全交互，避免了严重的循环依赖问题。

第一步：实现全局事件总线 (shared/infrastructure/event_bus.py)
事件总线负责模块间的发布-订阅通信，避免模块之间产生直接的代码强耦合。

Python
# shared/infrastructure/event_bus.py
from PySide2.QtCore import QObject, Signal

class EventBus(QObject):
    # 定义全局通用的事件信号，携带字典或任意数据
    event_published = Signal(str, dict)

    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super(EventBus, cls).__new__(cls)
            cls._instance._initialized = False
        return cls._instance

    def __init__(self):
        if self._initialized:
            return
        super().__init__()
        self._initialized = True
        self._subscribers = {}

    def publish(self, event_name: str, data: dict = None):
        """发布事件"""
        if data is None:
            data = {}
        # 既可以通过 Qt 信号分发，也可以通过内部回调分发
        self.event_published.emit(event_name, data)
        if event_name in self._subscribers:
            for callback in self._subscribers[event_name]:
                callback(data)

    def subscribe(self, event_name: str, callback):
        """订阅事件"""
        if event_name not in self._subscribers:
            self._subscribers[event_name] = []
        if callback not in self._subscribers[event_name]:
            self._subscribers[event_name].append(callback)

# 全局单例
event_bus = EventBus()

from shared.infrastructure.event_bus import event_bus

class AgentEngineService:
    def __init__(self):
        # 订阅 UI 层的事件
        event_bus.subscribe("request:send_clicked", self.handle_request)
        event_bus.subscribe("framework:changed", self.handle_framework_change)

    def handle_framework_change(self, data: dict):
        framework = data.get("framework", "")
        # 后续可在此对接具体的提示词模板加载逻辑
        print(f"[AgentEngine] 加载框架模板: {framework}")

    def handle_request(self, data: dict):
        raw_prompt = data.get("raw_prompt", "")
        framework = data.get("framework", "")
        
        # 模拟 AI 提示词组装与沙箱/大模型预处理逻辑
        final_prompt = f"--- [AI 提示词工程引擎] ---\n框架类型: {framework}\n原始内容:\n{raw_prompt}\n---------------------------"

            "final_prompt": final_prompt,

服务状态一直显示初始化，
这是一个典型的时序问题（Race Condition）：

原因分析：
在之前的代码中，modules/bridge/infrastructure/websocket_server.py 的最底部写了自动实例化语句（bridge_server = BridgeServer()）。当 main.py 导入该模块时，服务器会立即在模块加载阶段创建并发布 bridge:server_status 事件。
而此时，MainWindow 还没有被实例化，底部的状态栏和事件订阅 (event_bus.subscribe) 尚未完成，导致状态栏错过了这条广播消息，因此一直停留在“正在初始化...”状态。

解决方案：
取消模块底部的自动实例化，改在 main.py 的主函数中——在 MainWindow 创建并完成事件绑定之后，再显式实例化 BridgeServer。这样就能确保事件发布时，UI 已经准备好接收了。

# modules/bridge/infrastructure/websocket_server.py
import json
from PySide2.QtCore import QObject, Signal, Slot
from PySide2.QtWebSockets import QWebSocketServer, QWebSocket
from PySide2.QtNetwork import QHostAddress
from shared.infrastructure.event_bus import event_bus

class BridgeServer(QObject):
    """WebSocket 通信桥梁服务端"""

    message_received = Signal(dict)

    def __init__(self, port=9002, parent=None):
        super().__init__(parent)
        self.server = QWebSocketServer(
            "PySideExtensionBridge", QWebSocketServer.NonSecureMode, self
        )
        self.clients = []

        # 尝试监听端口并记录状态
        self.is_running = self.server.listen(QHostAddress.LocalHost, port)
        if self.is_running:
            print(f"[WebSocket] 服务启动成功，监听端口: {port}")
            self.server.newConnection.connect(self._on_new_connection)
        else:
            print(f"[WebSocket] 启动失败: {self.server.errorString()}")

        # 广播服务器整体运行状态
        event_bus.publish("bridge:server_status", {
            "is_running": self.is_running,
            "port": port,
            "error": "" if self.is_running else self.server.errorString()
        })

        # 初始化时广播初始未连接状态
        event_bus.publish("bridge:client_status", {"state": "init"})

        # 订阅下发指令事件
        event_bus.subscribe("bridge:send_to_extension", self._on_send_event)

    def _on_new_connection(self):
        client = self.server.nextPendingConnection()
        client.textMessageReceived.connect(self._on_text_received)
        client.disconnected.connect(lambda: self._on_disconnected(client))
        self.clients.append(client)
        print("[WebSocket] 浏览器插件已连接")
        # 广播已连接状态
        event_bus.publish("bridge:client_status", {"state": "connected"})

    def _on_disconnected(self, client):
        if client in self.clients:
            self.clients.remove(client)
            client.deleteLater()
            print("[WebSocket] 浏览器插件已断开")
            # 广播已断开状态
            event_bus.publish("bridge:client_status", {"state": "disconnected"})

    def _on_text_received(self, message):
        try:
            data = json.loads(message)
            self.message_received.emit(data)
            event_bus.publish("bridge:message_received", data)
        except json.JSONDecodeError:
            print(f"[WebSocket] 无法解析的非 JSON 消息: {message}")

    def _on_send_event(self, data: dict):
        text_msg = data.get("text", "")
        if text_msg:
            self.send_to_extension(text_msg)

    @Slot(str)
    def send_to_extension(self, text_msg):
        for client in self.clients:
            client.sendTextMessage(text_msg)
        print(f"[WebSocket] 已向插件发送文本指令: {text_msg}")

我插件断开了还是没有更新，是不是本地程序没有轮询连接状态
你的直觉非常敏锐！这里确实存在两个导致“断开状态不更新”的核心问题，你的猜测（需要轮询/心跳）恰好切中了 WebSockets 与浏览器插件通信的痛点。

原因分析：

“假死”连接（TCP 挥手丢失）： 尤其是 Chrome 插件（特别是 Manifest V3 的 Service Worker），当它被浏览器挂起、或者你直接刷新/重载插件时，它可能来不及向本地发送标准的 WebSocket Close 帧。此时本地 Qt 服务端会认为连接还在，disconnected 信号根本不会触发。这就需要你说的“轮询”或“心跳机制（Heartbeat）”来主动探测。

信号绑定的 Lambda 闭包问题： 在 PySide2 中，使用 client.disconnected.connect(lambda: self._on_disconnected(client)) 时，如果 client 对象没有被持续强引用，或者随着事件循环的作用域变化，这种写法有时会导致信号丢失。更稳妥的做法是使用 Qt 的 self.sender() 来获取发送信号的对象。

为了彻底解决这个问题，我们要在 BridgeServer 中引入 QTimer 心跳检测，并优化信号槽的绑定方式。

终极修复方案
更新 modules/bridge/infrastructure/websocket_server.py 代码。我们加入一个定时器，每 3 秒主动检查一次连接状态，同时向插件发送 Ping 帧（这也能防止 Chrome Manifest V3 插件因为不活跃而休眠）。

# modules/bridge/infrastructure/websocket_server.py
import json
from PySide2.QtCore import QObject, Signal, Slot, QTimer
from PySide2.QtWebSockets import QWebSocketServer, QWebSocket
from PySide2.QtNetwork import QHostAddress
from shared.infrastructure.event_bus import event_bus

class BridgeServer(QObject):
    """WebSocket 通信桥梁服务端（带心跳保活与状态轮询）"""

    message_received = Signal(dict)

    def __init__(self, port=9002, parent=None):
        super().__init__(parent)
        self.server = QWebSocketServer(
            "PySideExtensionBridge", QWebSocketServer.NonSecureMode, self
        )
        self.clients = []

        # 尝试监听端口并记录状态
        self.is_running = self.server.listen(QHostAddress.LocalHost, port)
        if self.is_running:
            print(f"[WebSocket] 服务启动成功，监听端口: {port}")
            self.server.newConnection.connect(self._on_new_connection)
            
            # --- 新增：启动心跳与状态轮询定时器 ---
            self.heartbeat_timer = QTimer(self)
            self.heartbeat_timer.timeout.connect(self._check_connections)
            self.heartbeat_timer.start(3000)  # 每 3 秒轮询一次
        else:
            print(f"[WebSocket] 启动失败: {self.server.errorString()}")

        # 广播服务器整体运行状态
        event_bus.publish("bridge:server_status", {
            "is_running": self.is_running,
            "port": port,
            "error": "" if self.is_running else self.server.errorString()
        })

        # 初始化时广播初始未连接状态
        event_bus.publish("bridge:client_status", {"state": "init"})

        # 订阅下发指令事件
        event_bus.subscribe("bridge:send_to_extension", self._on_send_event)

    def _on_new_connection(self):
        client = self.server.nextPendingConnection()
        client.textMessageReceived.connect(self._on_text_received)
        
        # 修复：放弃 lambda，直接绑定槽函数，在槽函数内使用 self.sender() 获取对象
        client.disconnected.connect(self._on_disconnected)
        
        self.clients.append(client)
        print("[WebSocket] 浏览器插件已连接")
        event_bus.publish("bridge:client_status", {"state": "connected"})

    def _on_disconnected(self):
        """处理正常的断开事件"""
        client = self.sender()
        self._remove_client(client)

    def _check_connections(self):
        """主动轮询检查连接状态（心跳机制）"""
        for client in list(self.clients):
            # 1. 检查底层 socket 状态是否已经不在连接中
            if client.state() != QWebSocket.ConnectedState:
                print("[WebSocket] 轮询检测到僵尸连接，执行清理")
                self._remove_client(client)
            else:
                # 2. 发送 ping 帧。一方面检测连通性，另一方面防止 Chrome 插件 Service Worker 休眠
                client.ping()

    def _remove_client(self, client):
        """统一清理失效客户端，并触发 UI 更新"""
        if client in self.clients:
            self.clients.remove(client)
            client.deleteLater()
            print(f"[WebSocket] 客户端已移除，当前剩余连接数: {len(self.clients)}")
            
        # 只有当所有客户端都断开时，才向 UI 广播“断开”状态
        if len(self.clients) == 0:
            event_bus.publish("bridge:client_status", {"state": "disconnected"})

    def _on_text_received(self, message):
        try:
            data = json.loads(message)
            self.message_received.emit(data)
            event_bus.publish("bridge:message_received", data)
        except json.JSONDecodeError:
            print(f"[WebSocket] 无法解析的非 JSON 消息: {message}")

    def _on_send_event(self, data: dict):
        text_msg = data.get("text", "")
        if text_msg:
            self.send_to_extension(text_msg)

    @Slot(str)
    def send_to_extension(self, text_msg):
        for client in self.clients:
            client.sendTextMessage(text_msg)
        print(f"[WebSocket] 已向插件发送文本指令: {text_msg}")
这个修复做了什么？
_check_connections 主动轮询：每隔 3 秒，程序会主动遍历所有 clients。如果发现某个客户端底层的 Socket 状态不再是 ConnectedState，就会立刻将其剔除并更新 UI。

Ping/Pong 心跳保活：通过 client.ping()，服务端会主动向 Chrome 插件发送轻量级的数据包。这对于 Chrome 插件极其重要，能强制延长浏览器插件后台的存活周期，避免它无故断开。

self.sender() 替换 Lambda：避免了 Python 垃圾回收或闭包作用域导致的信号丢失问题，确保插件只要正常触发断开，服务端必定能捕获。

多连接兼容：改为 if len(self.clients) == 0: 判断。如果你不小心在浏览器里打开了两个插件页面（产生两个连接），关掉其中一个时，只要另一个还连着，UI 依然会保持绿色的“已连接”。全部关掉才会变红。

from shared.infrastructure.event_bus import event_bus

class ShellController:
    """Shell 模块的应用层控制器，负责剥离 MainWindow 中的业务逻辑与事件编排"""

    def __init__(self):
        # 订阅全局返回结果，用于在控制器内部进行业务校验（如判空）
        event_bus.subscribe("request:result_ready", self.handle_result_validation)

    def handle_send_request(self, raw_text: str, framework: str):
        """处理用户点击发送请求的业务逻辑"""
        # 可以在此扩展更多前置业务校验（如校验 raw_text 长度、敏感词等）
        print(f"[ShellController] 触发请求发送，当前框架: {framework}")
        
        # 通过事件总线广播请求意图
        event_bus.publish("request:send_clicked", {
            "raw_prompt": raw_text,
            "framework": framework
        })

    def handle_framework_change(self, framework_name: str):
        """处理框架切换的业务逻辑"""
        event_bus.publish("framework:changed", {"framework": framework_name})

    def handle_result_validation(self, data: dict):

# modules/shell/presenters/agent_presenter.py
from shared.infrastructure.event_bus import event_bus

class AgentPresenter:
    """负责处理请求台与插件桥接的业务逻辑（MVP 中的 Presenter 层）"""

    def __init__(self, view):
        self.view = view
        # 订阅系统事件
        event_bus.subscribe("request:result_ready", self.handle_result_ready)
        event_bus.subscribe("bridge:server_status", self.handle_server_status)
        event_bus.subscribe("bridge:client_status", self.handle_client_status)

    def send_request(self, raw_text: str, framework: str):
        """处理用户点击发送的业务逻辑"""
        print(f"[AgentPresenter] 触发请求发送，当前框架: {framework}")
        event_bus.publish("request:send_clicked", {
            "raw_prompt": raw_text,
            "framework": framework
        })

    def change_framework(self, framework_name: str):
        """处理框架切换业务"""
        event_bus.publish("framework:changed", {"framework": framework_name})

    def handle_result_ready(self, data: dict):
        """处理 Agent 返回结果：校验最终提示词并决定是否推送给插件端"""
        final_prompt = data.get("final_prompt", "")
        parsed_result = data.get("parsed_result", "")

        # 通知 View 刷新界面
        self.view.update_results(final_prompt, parsed_result)

        # 业务规则校验：最终提示词不为空时才通过网关发送给插件
        if final_prompt and final_prompt.strip():
            event_bus.publish("bridge:send_to_extension", {"text": final_prompt})
            print("[AgentPresenter] 最终提示词校验通过，已向插件端口发送")
        else:
            print("[AgentPresenter] 最终提示词为空，已拦截，不向插件发送")

    def handle_server_status(self, data: dict):
        is_running = data.get("is_running", False)
        port = data.get("port", 9002)
        self.view.update_server_status(is_running, port, data.get("error", ""))

    def handle_client_status(self, data: dict):
        state = data.get("state", "init")
        self.view.update_client_status(state)
